# 다수 전투와 대시 기획안

타일 기반 실시간 전투에서 여러 몬스터에게 몰렸을 때의 문제와 해결 방향을 정리합니다. **구현 전 문서**이며, 구현되면 규칙은 [Combat.md](../GDD/Combat.md)와 [Monster_AI.md](../GDD/Monster_AI.md)로 옮깁니다.

## 1. 결정 사항 (유저, 2026-11-05)

| 항목 | 결정 |
| --- | --- |
| 전투 뼈대 | 타일 1칸 1몬스터 점유와 실시간 전투를 유지. 몬스터 간 공격 조율은 넣지 않고 시작 |
| 핵심 문제 | 끌어오기 자체가 아니라 **포위되면 움직이지 못하고 죽는 상황**과 피할 수 없는 공격. 빈도는 낮음 |
| 해결 수단 | **쿨타임이 있는 2칸 대시**. 회피, 포위 탈출, 공격 후 잠금 끊기를 모두 맡음 |
| 대시 규칙 | 2절 표 전체(몬스터 넘기 허용, 무적 없음, 잠금·걸음·차징 끊기, 공격 주기 유지) |
| 몬스터 근접 | 단일 근접과 치고 빠지기는 상하좌우 인접 칸에서만 시작. 광역 내려치기는 대각선도 유지 |
| 몬스터 투사체 | 새로 추가하지 않음. 예고형 장판을 선호. 기존 Magic Bolt 처리는 미정(6절) |

07 문서 Q4의 "후딜 캔슬 금지"는 이 결정으로 바뀌었습니다.

## 2. 대시 규칙

| 항목 | 규칙 |
| --- | --- |
| 입력 | `Space`. 선입력 슬롯을 거치지 않고 누른 즉시 처리 |
| 방향 | 누르고 있는 이동 방향. 없으면 마지막 이동 방향. 상하좌우만. 마우스 조준과 독립 |
| 거리·시간 | 2칸, 0.12초 (실험 초기값) |
| 쿨타임 | 3초 (실험 초기값). 발동 순간 시작. 일시정지 중에는 흐르지 않고, 층을 옮겨도 이어짐 |
| 넘어가기 | 경로 위의 몬스터를 넘어갈 수 있음 |
| 무적 | 없음. 판정 순간 서 있는 칸으로 맞음. 다른 장판 위에 착지하면 맞음. 피격 무적 0.5초는 기존 규칙 그대로 |
| 끊을 수 있는 것 | 공격 후 잠금, 진행 중인 1칸 걸음, 차징(모은 힘은 사라짐) |
| 공격 주기 | 대시로 초기화되지 않음. 이동 잠금만 풀리고 다음 공격은 원래 주기가 끝나야 가능 |
| 콤보 | 끊지 않음. 기존 유지 시간 1.5초 규칙 그대로 |
| 지나간 칸 | 아이템·계단·탈출구·안개 갱신은 착지 칸에서만 발동 |
| 표시 | 남은 쿨타임을 HUD에 표시 |

**착지 판정**

| 1칸째 | 2칸째 | 결과 |
| --- | --- | --- |
| 빈칸 | 빈칸 | 2칸 이동 |
| 빈칸 | 벽·상자·몬스터 | 1칸 이동 |
| 몬스터 | 빈칸 | 넘어가서 2칸째에 착지 |
| 몬스터 | 벽·상자·몬스터 | 발동 안 함, 쿨타임 소모 없음 |
| 벽·상자 | 무관 | 발동 안 함, 쿨타임 소모 없음 |

벽과 상자는 넘지 못합니다. 2×2 이상 보스는 2칸째도 점유하므로 자연스럽게 넘지 못합니다.

## 3. 왜 이 방향인가

코드 분석 결과(2026-11-05, 값은 코드·프리팹 기준 계산이며 게임 내 실측은 아님):

| 원인 | 내용 | 대시로 달라지는 점 |
| --- | --- | --- |
| 느린 회피 | 실제 이동은 칸당 **0.375초**(`0.3 × 10 / 속도 8`). 0.15초는 입력 간격이었음. 칸 경계를 넘는 데 0.19초 | 0.03초 만에 칸을 벗어남. 예고 0.45초의 여유가 0.01초 → 약 0.17초 (반응 0.25초 가정) |
| 잠금과 공격 주기가 같음 | 잠금 0.55초 중 예고 0.45초가 시작 후 0.29초 안에 뜨면 확정 피격 | 쿨타임을 써서 끊을 수 있음. 잠금은 무기의 대가로 유지 |
| 보이지 않는 칸 막힘 | 몬스터는 걷기 시작하는 순간 목적지 칸을 점유. 비어 보이는 칸으로 피하려 해도 이동이 취소됨 | 다른 칸으로 뛰거나 넘어갈 수 있음 |
| 완전 포위 | 공터 4마리, 벽 옆 3마리, 구석·1칸 길목 2마리면 이동 불가. 맨손으로 한 마리 뚫는 데 약 2~5초 | 몬스터를 넘어 탈출 |
| 공격 범위 비대칭 | 단일 근접 `maxRange` 2 + 체비쇼프 거리. 공격 시작 위치가 24칸인데 플레이어 이동은 4방향 | 근접 조건 수정으로 4칸으로 줄어듦 (대시와 별개) |

몬스터의 일렬 접근은 그대로 둡니다. 경로 탐색이 다른 몬스터를 장애물로 보지 않아 같은 길로 줄을 서는데, 유저가 이를 문제로 보지 않았고 창의 강점이 될 수 있습니다.

## 4. 검토한 대안

| 대안 | 판정 | 이유 |
| --- | --- | --- |
| 잠금과 공격 주기 분리 | 보류 | 대시가 잠금을 끊으므로 먼저 대시를 시험. Combat 2.1의 "움직일지 때릴지" 선택이 유지됨 |
| 이동 0.375초 → 0.25초 | 보류 | 첫 실험으로 부족하면 시험 |
| 탈출 칸 보호(예고 중 인접 칸 진입 금지) | 보류 | 위와 같음 |
| 자리바꿈(빈칸 없을 때) | 기각 | 대시가 포위 탈출까지 맡음 |
| 동시 공격 수·공격 시작 간격 제한 | 보류 | 빈도 문제가 아니라 탈출 문제로 정리됨. 필요할 때만 |
| 무리 경보, 역할 조합 | 보류 | 끌어오기 자체는 문제가 아님 |
| 이동 입력 패링, 몬스터끼리 맞는 공격 | 후보 | 필요할 때 시험 (*Demon Lord: Just a Block* 리뷰에서 착안) |
| 밀치기, 무적 중 통과 | 기각 | 밀치기는 포위에서 실패할 수 있고, 통과는 일부러 맞는 플레이를 만듦 |
| 8방향 이동, 자유 이동, 턴 연동 | 기각 | 뼈대 변경 비용이 크고 대시로 해결 가능 |

## 5. 다음 구현 단위와 첫 실험

CLAUDE.md 6단계 파이프라인으로 진행합니다. 수치는 인스펙터 값으로 두고 코드에 하드코딩하지 않습니다.

| 단위 | 내용 | 영향 범위 |
| --- | --- | --- |
| 1. 근접 조건 | `Pattern_SingleMelee` `maxRange` 2 → 1. 단일 근접·치고 빠지기의 발동 조건을 상하좌우 인접으로 | `SingleMeleePatternSO`, `HitAndRunPatternSO`, 패턴 에셋 |
| 2. 대시 코어 | 입력, 착지 판정, 칸 점유, 쿨타임, 잠금·걸음·차징 끊기 | `PlayerInput`, `PlayerController`, `PlayerMovement`, `EntityCombat`, `TileSystem` |
| 3. HUD | 쿨타임 표시 | 하단 HUD ([UI_Direction.md](../GDD/UI_Direction.md)) |

**구현 시 주의**

- `IsAttackOnCooldown`이 공격과 이동을 함께 막고 있습니다(`PlayerController` 이동 입력·`ExecuteStepMove`). 대시 후 걸을 수 있으려면 이동 잠금을 따로 풀어야 하며, 공격 주기는 그대로 둡니다.
- 걷는 중 대시는 이미 점유한 목적지 칸을 시작 칸으로 계산합니다. `CurrentTargetTileWorldPos`는 점유한 칸을 제거한 뒤의 경로를 보므로, 점유 칸을 따로 기억해야 합니다. 착지할 곳이 없으면 대시를 발동하지 않고 걸음을 계속합니다.
- 대시 중 `IsMoving`과 목적지 값은 곡사 포격·투사체의 위치 예측이 읽습니다(`MortarAoEPatternSO`, `RangedProjectilePatternSO`). 착지 칸을 돌려주게 합니다.
- 층 전환(`ResetForFloorTransition`)과 일시정지에서 대시를 정리합니다.

**첫 실험**

- 대상: 단위 1 + 2 (HUD 포함). 공격 주기는 실험값 0.55초 기준(6절).
- 상황: 공터 4마리 포위, 구석 2마리, 1칸 길목 앞뒤 협공, Brute + Spider 혼합.
- 볼 것: ① 피할 수 없다는 느낌이 줄었는가 ② 포위됐을 때 탈출할 수 있는가 ③ 쿨타임마다 무조건 누르는 정답 버튼이 되는가 ④ 대검처럼 잠금이 긴 조건에서 답답함이 줄었는가.
- 조정 순서: 쿨타임·거리 수치 → 이동 속도 → 잠금 분리 → 탈출 칸 보호.

대시 실험 뒤에 무기 3종을 진행합니다. 아래는 **미확정 초안**입니다.

| 무기 | 기본 범위 | 고유 규칙 |
| --- | --- | --- |
| 단검 | 1칸 | 빠른 공격 주기 + 측면·후방 보너스 |
| 창 | 직선 2칸 | 찌르며 적 뒤로 넘어가는 돌파 |
| 대검 | 전방 3칸 + 대각선 조준 시 양옆 | 제자리 충전 후 넓은 범위 + 넉백 |

무기 작업 전에 `WideSweep3`의 대각선 판정을 고쳐야 합니다. 지금은 북동쪽 조준 시 `(1,1), (0,2), (2,0)`을 때려 바로 옆 칸을 놓칩니다(`WeaponDataSO.PopulateHitboxCells`).
