# 층계 던전 기획안 (Floor-Based Dungeon)

> 작성일: 2026-11-02 / 상태: **기획 초안 — 유저 확정 전, 구현 금지**
> 이전 07번 문서(아이작형 방 그리드)는 유저 지시로 폐기하고 이 문서로 대체했다. 넓은 맵 1장 안(시작점 탈출, 귀환길·지름길·순찰조, 맵 프리뷰 3종)도 폐기된 안이다.
> 표기: **[확정]** = 유저가 정한 것, **[추천]** = Claude x Gemini 토론과 Claude 시뮬레이션에서 나온 수치(유저 미확정), **[쟁점]** = 아직 정하지 않은 것.

---

## 0. 개요

| 항목 | 내용 |
| --- | --- |
| 한 줄 요약 | 지역 4개 x 각 10층. 층마다 수작업 고정 층을 풀에서 뽑고, 탈출구는 확률로 나온다. 내려갈수록 가치가 오르고 가방이 찬다. 10층 보스를 잡으면 탈출 |
| 바꾸는 이유 | 넓은 통맵은 짧은 거리 카이팅(타일 스텝 + 장판 회피) 전투와 맞지 않는다. 작은 층을 여러 번 내려가며 매 층 "탈출구가 나오면 나갈까, 더 갈까"를 판단하게 한다 |
| 재사용 | 기존 `FixedMap` + `DungeonZone` 방식 그대로. 층 하나 = 작은 고정 프리팹 1장 |

## 1. 유저 확정 사항 [확정]

| # | 내용 |
| --- | --- |
| U1 | 지역(맵) 4개, 해금형. 지역 N 보스 첫 처치 **또는** 재료로 만든 통행증 → 지역 N+1 해금. 지역 4 보스 처치 = 엔딩 |
| U2 | 지역마다 10층. 10층은 보스층 고정, 보스 처치 시 탈출구 |
| U3 | 지역마다 층 디자인 풀(수작업 고정 층 여러 장)을 두고 층마다 랜덤/가중치로 뽑는다 |
| U4 | 탈출구는 "탈출구를 가질 수 있는 디자인"을 미리 정해 두고, 그 디자인에서 확률로 등장 |
| U5 | 탈출해야 내 것. 사망 시 가방·장비 전부 손실, 보안 파우치 2칸만 보존 (현재 구현과 같음) |
| U6 | 무게는 삭제된 기획. 가방은 칸 수만 제한 |

## 2. 기능 A — 층 디자인 풀과 층 생성

| 항목 | 내용 |
| --- | --- |
| **기능명** | 층 디자인 풀 (Floor Design Pool) |
| **핵심 로직** | 층 진입 시 현재 지역의 풀에서 "현재 층 번호가 등장 범위 태그에 들어가고, 이번 판에 아직 안 나온" 디자인을 가중치로 1장 뽑는다 → 프리팹 배치 → 기존 `DungeonGenerator` 구역 배치(BFS 도달 판정, 몬스터 간격 3칸, 시작점 5걸음 안전 반경) 그대로 수행 → 탈출구 판정(4절) |
| **데이터 [추천]** | `FloorDesignSO`: 프리팹, 등장 층 범위(예: 1~4, 3~7, 6~9), 가중치, 탈출구 가능 여부, 탈출구 위치 후보 2~3곳. `RegionConfigSO`: 지역 번호, 디자인 풀, 층별 몬스터 구성·배율 표, 보스층 디자인, 해금 조건 |
| **풀 크기 [추천]** | 지역당 8~12장, 한 판 안에서 중복 금지. 깊은 층은 지형을 재사용하고 몬스터 구성·배율로 난이도를 올린다 (1인 개발 제작량 절감) |
| **풀 크기 문제 (자체 검토)** | 1~9층을 중복 없이 채우려면 한 판에 디자인 **9장**이 필요하다. 8장이면 중복 금지가 성립하지 않고, 층 범위 태그(예: 1~4 / 3~7 / 6~9)로 나누면 범위마다 "그 범위 층 수 + 여유"만큼 있어야 한다. 또 4절 보정(100%)이 걸린 층에는 아직 안 쓴 **탈출구 가능 디자인**이 남아 있어야 한다. 선택지: ① 최소 12장 ② 중복 금지를 "직전 N층 내 중복 금지"(예: N=3)로 완화 → 8장으로도 가능 [쟁점 Q13] |
| **뷰/시청각** | 층 진입 시 "지역명 B3" 배너, 페이드 |
| **예외/제약** | 등장 가능 디자인이 0장이면(중복 금지로 소진) 중복 허용으로 다시 뽑고 경고 로그. 10층은 풀과 별개의 보스층 디자인 고정 |

**층 규모 [추천]**

| 층 | 바닥 칸 | 몬스터 | 상자(평균) | 예상 소요 |
| --- | --- | --- | --- | --- |
| 1 | 260 | 4 | 0.8 | 약 62초 |
| 5 | 340 | 6 | 1.2 | - |
| 9 | 380 | 7 | 1.5 | 약 85초 |
| 10 (보스) | 450 | 보스 1 + 잡몹 2 | - | - |

참고: 현재 FixedMap 통맵은 바닥 약 2,771칸이다. 층 하나는 그 1/10 안팎.

## 3. 기능 B — 층 이동

| 항목 | 내용 |
| --- | --- |
| **기능명** | 하강 (Descend) |
| **핵심 로직** | 층마다 하강 계단 1개(10층 제외). 계단 칸에서 확인창 → 다음 층 생성. 위층 복귀 없음 |
| **방식 [쟁점]** | ① 같은 씬에서 재생성: 타일맵·몬스터·상자·바닥 아이템·안개·`TileSystem` 예약을 지우고 다시 찍은 뒤 플레이어 순간이동. HP·UI·카메라 참조 유지. `ClearFloor()` 정리 누락 위험. ② 씬 재로드: 기존 던전 입장 경로 재사용. 단 현재 `PlayerStatManager.CalculateStats`가 첫 계산에서 `CurrentHp = MaxHp`로 채우고 `PlayerSessionData`에 HP 필드가 없어서, HP·MP·포션 쿨타임을 따로 저장해야 한다 |
| **HP·MP [쟁점]** | 층 간 유지(회복은 포션으로만) 추천 |
| **예외/제약** | 확인창 동안 `GamePauseService`로 일시정지. 취소하면 계단 칸을 벗어났다 다시 밟아야 재표시 |

## 4. 기능 C — 탈출구 확률

| 항목 | 내용 |
| --- | --- |
| **기능명** | 층 탈출구 (Floor Exit) |
| **핵심 로직** | 뽑힌 디자인이 탈출구 가능이면 층별 확률로 굴림 → 성공 시 위치 후보 2~3곳 중 1곳에 `DungeonExit` 배치. 탈출구 불가 디자인이면 굴리지 않음 |
| **확률 [추천]** | 1층 0%, 2~9층 25 / 35 / 45 / 55 / 65 / 75 / 85 / 95% |
| **보정 규칙 [추천]** | 직전 2개 층 연속 탈출구가 없으면 다음 층 100% (1층은 카운트하지 않음) → 첫 탈출 기회 2층 25% / 3층 26% / 4층 49%, 4층까지 100% 보장 |
| **보정과 디자인 충돌** | 보정으로 100%가 떴는데 뽑힌 디자인이 탈출구 불가이면 보장이 깨진다 → 보정이 걸린 층은 **탈출구 가능 디자인만 후보로** 뽑는다(풀마다 층 범위별로 탈출구 가능 디자인이 최소 1장 있어야 함) |
| **10층** | 보스 처치 시 탈출구 (U2) |
| **뷰/시청각** | 탈출구는 안개 속에서도 미탐험 칸이 아니면 표시(현재 고정 오브젝트 규칙과 같음) |
| **아이디어(미채택)** | 다음 층 탈출구 여부를 알려주는 나침반 소모품 |

**확률 의미**: 확률은 "뽑힌 디자인이 탈출구 가능일 때"의 조건부 확률인지, 층 전체 기준인지에 따라 실제 수치가 달라진다. 추천: **층 전체 기준**으로 보고, 굴림이 성공하면 탈출구 가능 디자인 중에서 뽑는다(먼저 굴리고 → 디자인 선택). 시뮬레이션 수치도 이 기준이다.

## 5. 기능 D — 드랍과 깊이 가치

| 항목 | 내용 |
| --- | --- |
| **일반 몬스터 [추천]** | 1마리당 65% 확률로 전리품 1개 (평균 0.65개) |
| **등급 비율 [추천·가정]** | Common 70 / Rare 25 / Legendary 5 |
| **상자 [추천]** | 재료 2 확정 + 30% 확률로 장비 또는 포션 |
| **정예·보스 [Claude 제안]** | 정예: 1개 확정 + 65% 1회 추가. 보스: Rare 이상 2개 확정 + 첫 처치 시 Legendary 1개 |
| **깊이 배율 [추천]** | 가치 배율 1층 1.0 → 5층 2.5 → 10층 10.0. 깊은 층은 드랍 **개수**가 아니라 등급 비율과 가치 배율을 올린다 |
| **전리품 = 재료** | 몬스터마다 테마 전리품 4~5종이 장비 해금 재료를 겸한다(기존 기획). 별도 범용 재료는 만들지 않는다 |
| **예외/제약** | 가치 배율을 "같은 아이템의 판매가 배율"로 할지 "깊은 층 전용 상위 아이템"으로 할지 [쟁점] — 같은 아이템이 층마다 값이 다르면 인벤토리 표시·스택 규칙이 꼬이므로 상위 아이템 쪽을 추천 |

## 6. 기능 E — 가방 압박

| 항목 | 내용 |

| **현재 구현** | 기본 30칸(허브 씬 `_baseMaxSlots: 30`, Player 프리팹 35), 재료 `maxStack` 대부분 10 |

## 7. 기능 F — 이동과 층 지형

| 항목 | 내용 |
| --- | --- |
| **이동 [추천]** | WASD 4방향 1칸 스텝 유지. 몬스터 A*도 4방향(`Pathfinder.cs`). 자유 이동·8방향 이동 기각 |
| **지형 규칙 [추천]** | 하이브리드 필드: 2칸 폭 오솔길·복도 + 7x7~9x9 공터. 1칸 병목은 길이 1~2칸만. 계단식 대각 벽 금지. 막다른 길은 짧은 파밍 포켓 |
| **지역별 이동 규칙 [추천]** | 지역마다 1개: 숲 = 턱 / 동굴 = 어둠·광원 / 성 지하 = 문·함정 / 불의 심층 = 용암·붕괴 바닥 |
| **1차 기믹 [추천]** | 장판 튜닝(예고 0.45초 이상, 3x3 중심에 갇히지 않게), 문 닫기(몬스터 1.5초 지연), 1칸 턱 일방통행 낙하, 넉백 + 벽 충돌 기절 |
| **2차 기믹 [추천]** | 이동 중 2칸 대시(후딜 캔슬 금지, 쿨 3초 — 도입 여부 [쟁점]), 덤불 은신, 감속 지형, 소음 타일, 부술 수 있는 잔해 |
| **근거** | 8방향 공격 장판을 4방향 이동 + 후딜 이동 불가로 피해야 하는 비대칭이 진짜 약점 → 1차는 장판 튜닝으로 대응 |

## 10. 기존 시스템 재사용·충돌

| 시스템 | 판정 | 내용 |
| --- | --- | --- |
| `DungeonGenerator` FixedMap + `DungeonZone` | 재사용 | 층 프리팹 안에 구역을 둔다. 탈출 포탈 "가장 먼 곳" 규칙은 "디자인이 정한 후보 중 랜덤"으로 교체 |
| `ProceduralChunks` / `DungeonChunk` / `DungeonData` | 정리 대상 | 청크 조립은 이 기획에서 쓰지 않는다. 삭제 또는 보류 [쟁점] |
| `FogOfWarSystem` | 재사용 | 층마다 `Initialize` 다시 호출. 같은 씬 재생성이면 안개 타일맵 초기화 필요 |
| `MonsterController` / `MonsterDataSO` | 확장 | 층 배율(HP·ATK) 적용 지점 필요. `MonsterType.Boss` 전용 패턴 없음 → 10층 보스 제작 필요 |
| `DungeonExit` / `RunResult` | 재사용 + 확장 | 결과 화면에 지역·도달 층 표시 |
| `PlayerSessionData` | 확장 | 현재 지역·층·연속 무탈출 카운트, (씬 재로드 방식이면) HP·MP |
| 보안 파우치 / 사망 처리 | 변경 없음 | U5 |
| 인벤토리 `SlotContainer` | 데이터 변경 | 기본 칸 수, 재료 `maxStack` 값만 바뀜. 코드 변경 없음 |
