# 층계 던전 기획안 (Floor-Based Dungeon)

> 작성일: 2026-11-02 / 상태: **기획 초안 v2 (Gemini 기획 검토 반영, 13절) — 유저 확정 전, 구현 금지**
> 이전 07번 문서(아이작형 방 그리드)는 유저 지시로 폐기하고 이 문서로 대체했다. 넓은 맵 1장 안(시작점 탈출, 귀환길·지름길·순찰조, 맵 프리뷰 3종)도 폐기된 안이다.
> 표기: **[확정]** = 유저가 정한 것, **[추천]** = Claude x Gemini 토론과 Claude 시뮬레이션에서 나온 수치(유저 미확정), **[쟁점]** = 아직 정하지 않은 것.

---

## 0. 개요

| 항목 | 내용 |
| --- | --- |
| 한 줄 요약 | 지역 4개 x 각 10층. 층마다 수작업 고정 층을 풀에서 뽑고, 탈출구는 확률로 나온다. 내려갈수록 가치가 오르고 가방이 찬다. 10층 보스를 잡으면 탈출 |
| 바꾸는 이유 | 넓은 통맵은 짧은 거리 카이팅(타일 스텝 + 장판 회피) 전투와 맞지 않는다. 작은 층을 여러 번 내려가며 매 층 "탈출구가 나오면 나갈까, 더 갈까"를 판단하게 한다 |
| 재사용 | 기존 `FixedMap` + `DungeonZone` 방식 그대로. 층 하나 = 작은 고정 프리팹 1장 |

## 1. 유저 확정 사항 [확정]

| # | 내용 |
| --- | --- |
| U1 | 지역(맵) 4개, 해금형. 지역 N 보스 첫 처치 **또는** 재료로 만든 통행증 → 지역 N+1 해금. 지역 4 보스 처치 = 엔딩 |

| U4 | 탈출구는 "탈출구를 가질 수 있는 디자인"을 미리 정해 두고, 그 디자인에서 확률로 등장 |

## 2. 기능 A — 층 디자인 풀과 층 생성

| 항목 | 내용 |
| --- | --- |
| **기능명** | 층 디자인 풀 (Floor Design Pool) |
| **핵심 로직** | 층 진입 시 ① 탈출구 굴림(4절 확률·보정) → ② 현재 지역 풀에서 "현재 층 번호가 등장 범위 태그에 들어가고, 중복 규칙(Q13)에 걸리지 않고, ①이 성공했으면 탈출구 가능인" 디자인을 가중치로 1장 뽑는다 → 프리팹 배치 → 기존 `DungeonGenerator` 구역 배치(BFS 도달 판정, 몬스터 간격 3칸, 시작점 5걸음 안전 반경) 그대로 수행 → ①이 성공했으면 탈출구 후보 중 1곳에 배치. (순서를 "굴림 먼저"로 통일 — Gemini 검토 MAJOR 1) |
| **데이터 [추천]** | `FloorDesignSO`: 프리팹, 등장 층 범위(예: 1~4, 3~7, 6~9), 가중치, 탈출구 가능 여부, 탈출구 위치 후보 2~3곳. `RegionConfigSO`: 지역 번호, 디자인 풀, 층별 몬스터 구성·배율 표, 보스층 디자인, 해금 조건 |
| **풀 크기 [추천]** | 지역당 8~12장, 한 판 안에서 중복 금지. 깊은 층은 지형을 재사용하고 몬스터 구성·배율로 난이도를 올린다 (1인 개발 제작량 절감) |
| **풀 크기 문제 (자체 검토)** | 1~9층을 중복 없이 채우려면 한 판에 디자인 **9장**이 필요하다. 8장이면 중복 금지가 성립하지 않고, 층 범위 태그(예: 1~4 / 3~7 / 6~9)로 나누면 범위마다 "그 범위 층 수 + 여유"만큼 있어야 한다. 또 4절 보정(100%)이 걸린 층에는 아직 안 쓴 **탈출구 가능 디자인**이 남아 있어야 한다. 선택지: ① 최소 12장 ② 중복 금지를 "직전 N층 내 중복 금지"(예: N=3)로 완화 → 8장으로도 가능 [쟁점 Q13] |
| **뷰/시청각** | 층 진입 시 "지역명 B3" 배너, 페이드 |
| **예외/제약** | 후보가 0장이면 조건을 순서대로 풀어 다시 뽑는다: 중복 규칙 해제 → 층 범위 태그 해제 → (탈출구 조건은 마지막까지 유지). 풀 때마다 경고 로그. 제작 규칙: 각 층 범위 태그마다 탈출구 가능 디자인 최소 2장(Gemini 검토 MAJOR 2: 범위 태그 + 중복 금지 + 탈출구 보정이 겹치면 후보 0장). 대안으로 범위 태그를 없애고 난이도는 배율로만 올리는 안도 있음 [Q13]. 10층은 풀과 별개의 보스층 디자인 고정 |

**층 규모 [추천]**

| 층 | 바닥 칸 | 몬스터 | 상자(평균) | 예상 소요 |
| --- | --- | --- | --- | --- |
| 1 | 260 | 4 | 0.8 | 약 62초 |
| 5 | 340 | 6 | 1.2 | - |
| 9 | 380 | 7 | 1.5 | 약 85초 |

## 3. 기능 B — 층 이동

| 항목 | 내용 |
| --- | --- |
| **기능명** | 하강 (Descend) |
| **핵심 로직** | 층마다 하강 계단 1개(10층 제외). 계단 칸에서 확인창 → 다음 층 생성. 위층 복귀 없음 |
| **방식 [쟁점]** | ① 같은 씬에서 재생성: 타일맵·몬스터·상자·바닥 아이템·안개·`TileSystem` 예약을 지우고 다시 찍은 뒤 플레이어 순간이동. HP·UI·카메라 참조 유지. 주의: 현재 `DungeonGenerator.SpawnPlayerAtCell`은 플레이어 프리팹을 매번 `Instantiate`하므로, 그대로 쓰면 새 플레이어의 `_isInitialized`가 false라 HP가 다시 가득 찬다 → 2층부터는 기존 플레이어를 **재사용하고 위치만 옮기는** 분기가 필요(Gemini 검토 MAJOR 3). `ClearFloor()` 정리 대상: 층 프리팹, 몬스터, 상자, 바닥 아이템, 투사체·장판, 안개 타일맵(`ClearAllTiles` 후 `Initialize` 재호출), `TileSystem` 점유·예약·위험 칸(현재 전체 초기화 메서드 없음 → 추가 필요). 누락 시 보이지 않는 벽·안개 잔상(Gemini 검토 MINOR 2). ② 씬 재로드: 기존 던전 입장 경로 재사용. 단 현재 `PlayerStatManager.CalculateStats`가 첫 계산에서 `CurrentHp = MaxHp`로 채우고 `PlayerSessionData`에 HP 필드가 없어서, HP·MP·포션 쿨타임을 따로 저장해야 한다 |
| **HP·MP [쟁점]** | 층 간 유지(회복은 포션으로만) 추천 |
| **예외/제약** | 확인창 동안 `GamePauseService`로 일시정지(투사체·장판 피해도 멈춤). 취소하면 계단 칸을 벗어났다 다시 밟아야 재표시. 계단 칸과 주변 1칸은 몬스터 스폰 금지, 계단은 막다른 1칸 골목에 두지 않는다(몬스터에게 막혀 못 벗어나는 상황 방지 — Gemini 검토 MINOR 1) |

## 4. 기능 C — 탈출구 확률

| 항목 | 내용 |
| --- | --- |
| **기능명** | 층 탈출구 (Floor Exit) |
| **핵심 로직** | 뽑힌 디자인이 탈출구 가능이면 층별 확률로 굴림 → 성공 시 위치 후보 2~3곳 중 1곳에 `DungeonExit` 배치. 탈출구 불가 디자인이면 굴리지 않음 |
| **확률 [추천]** | 1층 0%, 2~9층 25 / 35 / 45 / 55 / 65 / 75 / 85 / 95% |
| **보정 규칙 [추천]** | 직전 2개 층 연속 탈출구가 없으면 다음 층 100% (1층은 카운트하지 않음) → 첫 탈출 기회 2층 25% / 3층 26% / 4층 49%, 4층까지 100% 보장 |
| **보정과 디자인 충돌** | 보정으로 100%가 떴는데 뽑힌 디자인이 탈출구 불가이면 보장이 깨진다 → 보정이 걸린 층은 **탈출구 가능 디자인만 후보로** 뽑는다(풀마다 층 범위별로 탈출구 가능 디자인이 최소 1장 있어야 함) |
| **10층** | 보스 처치 시 탈출구 (U2) |
| **뷰/시청각** | 탈출구는 안개 속에서도 미탐험 칸이 아니면 표시(현재 고정 오브젝트 규칙과 같음) |
| **아이디어(미채택)** | 다음 층 탈출구 여부를 알려주는 나침반 소모품 |

**확률 의미**: 확률은 "뽑힌 디자인이 탈출구 가능일 때"의 조건부 확률인지, 층 전체 기준인지에 따라 실제 수치가 달라진다. 추천: **층 전체 기준**으로 보고, 굴림이 성공하면 탈출구 가능 디자인 중에서 뽑는다(먼저 굴리고 → 디자인 선택). 시뮬레이션 수치도 이 기준이다.

## 6. 기능 E — 가방 압박

| 항목 | 내용 |
| --- | --- |
| **목표** | 5~6층에서 가방이 거의 차서, 7층부터는 버리고 바꿔 담는 판단이 생기게 |
| **현재 구현** | 기본 30칸(허브 씬 `_baseMaxSlots: 30`, Player 프리팹 35), 재료 `maxStack` 대부분 10 |
| **문제(시뮬레이션)** | 현재 스택(재료 10)이면 9층까지 가도 약 16칸 → 가방이 차지 않는다 |
| **변경 [추천]** | 기본 25칸(+Basic Backpack 10 = 35칸), 재료 `maxStack` Common 3 / Rare 1 / Legendary 1. 포션 5, 장비 1 유지 |
| **시뮬레이션 결과** | 시작 포션 2칸 포함 5층 약 19칸(77%), 6층 약 23칸(92%), 7층부터 초과 — **배낭 미착용 25칸 기준** |
| **배낭 착용 시 (Gemini 검토 MAJOR 4)** | 기본 배낭(+10)을 차고 들어가면 35칸이라 6층 약 23칸 = 66%로 압박 목표가 깨진다. 배낭은 기지에서 쉽게 얻는 장비라 대부분 차고 들어갈 것으로 봐야 한다. 선택지 [Q15]: ① 기본 20칸 + 배낭 10 = 30칸(6층 약 77%) ② 기본 25칸 유지, 배낭 보너스를 +5로 축소(30칸) ③ 드랍 수를 35칸 기준으로 상향. 추천: ② — 기본 칸이 너무 작으면 배낭 없는 첫 런에서 포션 2칸 + 전리품만으로 2~3층에 막힘 |
| **[쟁점]** | 7층 이후 버리기·교체 UX(바닥 버리기·휴지통은 구현됨, 줍기 전 비교 UI는 없음), 보안 파우치 2칸의 보험 가치 |
| **파우치 이동 시점 [IDEA, Q16]** | 던전 안에서 언제든 파우치로 옮길 수 있으면 좋은 아이템을 줍자마자 대피시켜 긴장감이 떨어진다(Gemini 제안). 선택지: 제한 없음(현재 구현) / 비전투 상태에서만 / 기지에서 출발 전에만 |

## 8. 기능 G — 지역 해금과 엔딩

| 항목 | 내용 |
| --- | --- |
| **핵심 로직** | 지역 N 보스 첫 처치 → 지역 N+1 해금 플래그. 또는 기지에서 재료로 통행증 제작 → 해금 [확정] |
| **데이터** | 해금 상태 영구 저장. 현재는 디스크 저장이 없다(`SaveData.cs`의 `InventorySaveData` 등은 직렬화용 POCO 정의뿐, `PlayerSessionData`는 static 메모리라 게임을 끄면 사라짐) → 세이브 구조 필요 |
| **[쟁점]** | 통행증 재료 종류·수량, 통행증이 소모품인지 영구 해금인지, 해금 후 이전 지역 재방문 가능 여부(추천: 가능) |
| **엔딩** | 지역 4 보스 처치. 이후 하드 모드(Heat) 해금으로 연결 (Roadmap 6절) |

## 10. 기존 시스템 재사용·충돌

| 시스템 | 판정 | 내용 |
| --- | --- | --- |
| `DungeonGenerator` FixedMap + `DungeonZone` | 재사용 | 층 프리팹 안에 구역을 둔다. 탈출 포탈 "가장 먼 곳" 규칙은 "디자인이 정한 후보 중 랜덤"으로 교체 |
| `ProceduralChunks` / `DungeonChunk` / `DungeonData` | 정리 대상 | 청크 조립은 이 기획에서 쓰지 않는다. 삭제 또는 보류 [쟁점] |
| `FogOfWarSystem` | 재사용 | 층마다 `Initialize` 다시 호출(`PopulateInitialFog`가 안개 타일맵 `ClearAllTiles` 후 다시 채움). 탐험 상태 캐시도 비워지는지 구현 시 확인 |
| `DungeonGenerator.SpawnPlayerAtCell` | 수정 | 매번 `Instantiate` → 같은 씬 재생성이면 2층부터 기존 플레이어 위치만 이동 |
| `TileSystem` | 확장 | 점유·예약·위험 칸 전체 초기화 메서드 없음 → 추가 |
| `MonsterController` / `MonsterDataSO` | 확장 | 층 배율(HP·ATK) 적용 지점 필요. `MonsterType.Boss` 전용 패턴 없음 → 10층 보스 제작 필요 |
| `DungeonExit` / `RunResult` | 재사용 + 확장 | 결과 화면에 지역·도달 층 표시 |
| `PlayerSessionData` | 확장 | 현재 지역·층·연속 무탈출 카운트, (씬 재로드 방식이면) HP·MP |
| 보안 파우치 / 사망 처리 | 변경 없음 | U5 |
| 인벤토리 `SlotContainer` | 데이터 변경 | 기본 칸 수, 재료 `maxStack` 값만 바뀜. 코드 변경 없음 |
