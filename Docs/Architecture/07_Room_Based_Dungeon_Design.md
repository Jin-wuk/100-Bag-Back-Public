# 방 단위 던전 구조 기획안 (Room-Based Dungeon)

> 작성일: 2026-10-31 / 상태: **기획 초안 v2 (Gemini 기획 검토 반영, 12절) — 유저 확정 전, 구현 금지**
> 출발점(유저 원문): "아이작형태의 맵생성을 하면서 단계를 나누고 높은단계에서는 확률적으로 보스몬스터가 나오게끔하는게 어떨까 싶네. 현재 게임코어 플레이스타일은 넓은 맵을 돌아다니기에는 별로인거같아."
> 이 문서의 수치는 전부 **추천안**이다. 9절 질문에 유저가 답하기 전에는 확정이 아니다.

---

## 0. 문제 정의

| 현재 | 문제 |
| --- | --- |
| 수작업 통맵 1장 + `DungeonZone` 구역 (FixedMap) | 맵이 넓어 이동 시간 대비 전투 밀도가 낮다 |
| 전투는 타일 1칸 이동 + 8방향 조준 + 장판 예고 회피 | 짧은 거리 카이팅이 핵심인데, 통맵에서는 복도 1:1이나 열린 공간 1:N이 우연에 맡겨진다 |
| 탈출 포탈은 시작점에서 BFS로 가장 먼 곳 1개 | "더 갈까, 나갈까" 판단 지점이 없다. 깊이 개념이 없다 |

**목표**: 화면 하나 크기의 방을 그리드로 이어 붙인 층(단계)을 만들고, 층을 내려갈수록 보상과 위험이 함께 오르며, 높은 층에서 보스가 확률로 등장하게 한다. 매 층마다 "탈출 vs 다음 층" 선택을 준다.

**레퍼런스와의 차이** (아이작은 방 그리드 생성 방식만 참고):

- 아이작은 층 클리어가 목적인 로그라이크, 이 게임은 **가방에 담아 살아 나가는 익스트랙션**이다. 층마다 탈출구가 있고, 깊이 갈지는 플레이어가 고른다.
- 전투는 실시간 탄막이 아니라 **타일 스텝 + 장판 예고**다. 방 크기와 장애물은 카이팅 공간 기준으로 잡는다.
- 방 안에도 **전장의 안개**(시야 4칸)가 남는다. 방 전체가 한눈에 보이지 않는다.
- 모든 방이 문을 잠그지 않는다(5절). 도주가 가능해야 익스트랙션 긴장감이 산다.

## 1. 현재 구현과 재사용·충돌 지점

| 시스템 | 현재 | 방 구조에서 | 판정 |
| --- | --- | --- | --- |
| `DungeonGenerator` | `FixedMap`(구역 BFS 배치) / `ProceduralChunks`(그리드 슬롯에 청크 프리팹, 골격만) | 세 번째 모드 `RoomGrid` 추가. 청크 그리드 골격(`_spawnedChunks`, 오프셋 배치)과 구역 기반 엔티티 배치 로직(`SpawnEntitiesInCells`, 간격 규칙) 재사용 | 확장 |
| `DungeonChunk` / `DungeonData` | 청크 프리팹 + 3x3 슬롯 + 청크당 몬스터 수 | 방 템플릿 프리팹(`RoomTemplate`)과 층 설정 SO(`FloorConfig`)로 발전. 기존 "4면 출입구 위치 고정" 규칙이 그대로 문 규격이 됨 | 확장 또는 대체 (Q9) |
| `DungeonZone` | 통맵 위 박스 구역 (Start/Combat/Chest/Corridor/Exit) | 방 템플릿 안의 **스폰 영역 마커**로 재사용. 방 종류는 방 단위로 정하고, 구역은 방 안에서 "어디에 놓을지"만 담당 | 재사용 |
| BFS 도달 판정 | 타일 단위, 시작점→가장 먼 Exit | 타일 BFS는 방 안 배치용으로 유지. 특수방 배치는 **방 그래프 BFS**(방 간 거리)로 | 재사용 + 추가 |
| `FogOfWarSystem` | 타일 3단계 안개, 북쪽 벽 보정, 이동 시 갱신 | 그대로 동작(모든 방이 한 타일맵 위라면). 방 진입 시 방 지형 일괄 "탐험" 처리 옵션(Q7) | 재사용 + 옵션 |
| `MonsterController` | ZOC 감지, 6초 어그로, 추적 한계 `zocRadius+4` | 추적 한계를 **자기 방 경계**로 바꿔야 함. 안 그러면 문을 넘어 다른 방까지 따라오고, 문 잠금·방 클리어 판정이 깨짐 | 수정 필요 |
| `MonsterType` (Normal/Elite/Boss) | enum만 존재, 등급별 규칙·보스 패턴 없음 | 보스방 스폰 대상. 보스 전용 패턴은 아직 없음 → 6절 임시 보스안 | 추가 개발 |
| `Pathfinder` (A*, `Physics2D.OverlapPoint`) | 장애물 레이어 충돌 검사 | 잠긴 문은 장애물 레이어 콜라이더여야 몬스터·플레이어 모두 막힘 | 재사용 |
| `CameraFollow` | 플레이어 스무스 추적 + 쉐이크·히트스톱 | 방 경계 안으로 카메라 위치 제한(clamp) + 방 전환 시 슬라이드 추가 | 확장 |
| `DungeonExit` | 포탈 칸 진입 → `RunResult(true)` → 허브 로드 | 층마다 탈출방에 배치, 그대로 사용 | 재사용 |
| `PlayerStatManager.HandleDeath` / 보안 파우치 | 사망 시 가방·장비 소실, 파우치 보존 | 변경 없음 | 재사용 |
| `RunResult` / `RunResultUI` | 가져온 것·잃은 것·가치 | "도달 층", "처치 보스" 표시 필드 추가 | 확장 |
| `PlayerSessionData` (static) | 씬 전환 간 가방·장비·파우치 유지 | 층 이동을 씬 재로드로 하면 그대로 유지됨. **HP·MP는 유지 안 됨**: `PlayerStatManager.CalculateStats`가 첫 계산 때 `CurrentHp = MaxHp`로 채우고, `PlayerSessionData`에 HP 필드가 없음 | 수정 필요 (Q8) |

## 2. 기능 A — 층(방 그리드) 생성

| 항목 | 내용 |
| --- | --- |
| **기능명** | 층 레이아웃 생성 (Floor Layout) |
| **핵심 로직** | ① 가상 그리드(추천 7x7) 중앙에 시작방. ② 이미 놓인 방 중 하나를 골라 빈 이웃 칸으로 확장, **새 칸의 이웃 방이 1개일 때만** 허용(루프·덩어리 방지 → 트리형). 목표 방 개수에 도달할 때까지 반복. ③ 방 그래프 BFS로 시작방 기준 거리 계산. ④ 막다른 방(이웃 1개) 목록에서 특수방 배정: 가장 먼 곳 = 계단방(또는 보스방), 그다음 먼 곳 = 탈출방. 보물방은 남은 막다른 방 우선, 없으면 **일반 방 중 시작방과 거리 2 이상인 곳**(막다른 방 필수 아님 — 검토 C1). ⑤ 막다른 방이 2개 미만이면 재생성(최대 N회, 실패 시 고정 레이아웃 폴백). ⑥ 나머지 = 전투방, 일부는 빈 방(휴식/함정)으로. |
| **데이터** | `FloorConfig` SO (층별): 방 개수 범위, 몬스터 풀, 몬스터 수 범위, 보스 확률, 스탯·드랍 배율. `RoomTemplate` 프리팹: 방 종류 태그, 문 4면 위치(고정), 내부 장애물, `DungeonZone` 스폰 마커. 시드(디버그 재현용) |
| **뷰/시청각** | 방 종류별 문틀 색·아이콘(보물/탈출/계단/보스). 미니맵(Q7) |
| **예외/제약** | 탈출방과 계단방은 같은 방이 될 수 없음. 시작방에는 몬스터 없음. 보물방은 시작방 인접 금지(추천). 템플릿이 부족한 방 종류는 전투방 템플릿으로 대체 + 경고 로그 |

**추천 수치 (Q1·Q2)**

| 층 | 방 개수 | 특수방 |
| --- | --- | --- |
| 1층 | 7~8 | 시작, 탈출, 계단, 보물 1 |
| 2층 | 8~9 | 시작, 탈출, 계단, 보물 1 |
| 3층 (노멀 마지막) | 10~11 | 시작, 탈출, 보스(확률) 또는 정예, 보물 1~2 |

**방 크기 (Q3)**: 현재 카메라 orthographic size 8 → 화면 세로 16칸, 16:9 기준 가로 약 28칸. 내부 바닥 **17x11칸**(외벽 포함 19x14, 북쪽 벽 2칸 높이 반영) 추천. 한 화면에 방 전체 + 하단 HUD 여유가 들어가고, 원거리 몬스터(ZOC 7)와 카이팅할 거리가 나온다. 13x9는 좁아 1:N에서 회피 공간 부족, 21x13은 세로가 화면을 넘는다. 큰 방(2x1, L자)은 1차 범위에서 제외.

## 3. 기능 B — 방 배치와 전환

| 항목 | 내용 |
| --- | --- |
| **기능명** | 방 조립과 방 전환 (Room Assembly & Transition) |
| **핵심 로직 (추천: 연속 월드)** | 층 생성 시 모든 방 템플릿을 **하나의 Grid·타일맵 위에** 그리드 좌표 × 방 크기 오프셋으로 붙여 찍는다. 이웃한 방은 벽을 공유하고, 연결된 면은 문 칸(바닥)을, 연결 안 된 면은 벽을 찍는다. 플레이어는 문 칸을 그냥 걸어서 넘어간다. 방 경계를 넘는 순간 `CurrentRoom` 갱신 → 카메라 clamp 대상 변경 + 방 진입 이벤트 |
| **대안** | 방마다 따로 활성화/비활성화하고 문에서 순간이동. 성능은 유리하나 안개·A*·TileSystem 예약을 방마다 다시 초기화해야 해서 기존 코드 재사용이 줄어든다. 방 수 11개 × 17x11 = 약 2,000칸이라 연속 월드로도 부담 없음 |
| **카메라** | 방 경계 안으로 clamp. 방 전환 시 0.25~0.35초 슬라이드(추천), 이동 입력은 슬라이드 중 0.2초 잠금 |
| **데이터** | `RoomInstance` 런타임: 그리드 좌표, 종류, 월드 경계(BoundsInt), 문 4개 상태, 소속 몬스터 목록, 클리어 여부 |
| **뷰/시청각** | 문: 열림/잠김 스프라이트 2종, 잠길 때 SE + 짧은 쉐이크. 아트 세션 타일과 문 규격(폭 1칸 or 2칸) 맞춤 필요 |
| **예외/제약** | 문 칸과 문 전후 1칸은 **몬스터 이동·스폰 금지 구역**, 상자·함정 스폰도 금지(검토 M3). 원거리 몬스터(`RangedKiting`)는 문에서 6칸 이상 떨어진 마커에만 스폰(검토 m1). 문이 잠기는 시점은 플레이어가 문을 지나 방 안쪽 2칸 이상 들어온 뒤 → 문 칸에 몬스터가 끼는 상황 자체를 없애고 밀어내기 로직은 만들지 않는다 |

## 4. 기능 C — 단계(층) 진행

| 항목 | 내용 |
| --- | --- |
| **기능명** | 층 이동 (Descend) |
| **핵심 로직** | 계단방의 계단 칸에 서서 상호작용(추천: 확인창 "다음 층으로 내려갑니다. 돌아올 수 없습니다") → 현재 층 번호 +1 → 던전 씬 재로드 + 새 층 생성. 위층으로 돌아가기 없음 |
| **데이터** | `PlayerSessionData.CurrentFloor`(신규), 층별 `FloorConfig` 목록(노멀 3개 추천, Q2). 층 간 유지: 가방·장비·파우치(이미 유지), **HP·MP·포션 쿨타임**(Q8) |
| **뷰/시청각** | 층 진입 시 "B2" 같은 층 표시 배너, 짧은 페이드 |
| **방식 (Q14)** | ① 씬 재로드: 기존 던전 입장 경로 재사용, 정리(cleanup)가 자동. 대신 HP·MP·포션 쿨타임을 `PlayerSessionData`에 저장해야 함. ② 같은 씬에서 재생성(검토 C2 제안): 타일맵·몬스터·상자·바닥 아이템·안개·`TileSystem` 예약을 전부 지우고 다시 찍은 뒤 플레이어 순간이동. HP·UI·카메라 참조는 그대로 유지되지만 정리 누락 버그 위험이 있음. 추천: **②** — 층 이동은 런 안에서 반복되는 동작이라 상태 직렬화 범위를 늘리지 않는 쪽이 낫다. 단 생성기에 `ClearFloor()`가 필요 |
| **예외/제약** | 계단 확인창이 떠 있는 동안 몬스터 공격 처리(일시정지 vs 진행). 추천: `GamePauseService`로 일시정지 — 가방 일시정지 규칙과 동일. 확인창에서 취소하면 계단 칸을 벗어났다 다시 밟아야 재표시(검토 m2) |

## 5. 기능 D — 방 클리어와 문 잠금

| 항목 | 내용 |
| --- | --- |
| **기능명** | 방 전투 규칙 (Room Lock & Clear) |
| **선택지** | A) 모든 전투방 잠금 → 전멸 시 열림 (아이작식, 전투 강제). B) 잠금 없음, 몬스터는 방 밖으로 추적하지 않음 (도주 자유). **C) 혼합 (추천)**: 일반 전투방은 잠기지 않음, 정예방·보스방만 잠금 |
| **C안 근거** | 익스트랙션은 "싸울지 피할지"가 핵심 판단이다. 전부 잠그면 HP가 낮을 때 탈출방으로 도망치는 선택이 사라진다. 정예·보스방만 잠그면 "들어가면 끝까지"라는 위험한 선택지로 기능한다 |
| **핵심 로직** | 몬스터 추적 한계 = 자기 방 경계(문 칸 제외). 플레이어가 방을 나가면 해당 방 몬스터는 어그로 해제 후 스폰 위치로 복귀(점유돼 있으면 BFS로 가장 가까운 빈 칸 — 검토 m3) + HP 유지(추천) 또는 완전 회복. 잠금방: 플레이어 진입 → 문 잠금 → 소속 몬스터 전멸 → 문 열림 + 보상(상자/골드) |
| **방 상태 유지** | 같은 층 안에서는 방 상태 유지(죽은 몬스터 부활 안 함, 바닥 아이템 남음). 연속 월드라 별도 저장 불필요 |
| **데이터** | `RoomInstance.isLockable`, `OnRoomEntered`, `OnRoomCleared` 이벤트 |
| **예외/제약** | `EXPLOSIVE` 사망 폭발이 끝나기 전 문이 열리는 것은 허용. 잠금방 안에서 사망 → 일반 사망과 동일. 몬스터가 문 칸에 끼인 채 잠기는 경우 → 잠금 직전 문 칸 몬스터를 방 안쪽으로 밀어냄 |

## 6. 기능 E — 보스 확률 등장

| 항목 | 내용 |
| --- | --- |
| **기능명** | 층 보스 (Floor Boss) |
| **핵심 로직** | 층 생성 시 `FloorConfig.bossChance`로 굴림. 성공 → 가장 먼 막다른 방이 보스방(잠금), 보스 처치 시 그 방에 **계단 + 보너스 탈출 포탈** 생성. 실패 → 그 방은 일반 계단방(또는 마지막 층이면 정예방). 탈출방은 보스와 별개로 항상 존재 → 보스를 피해서 나갈 수 있다 |
| **추천 확률 (Q4)** | 1층 0%, 2층 25%, 3층 60%. (대안: 마지막 층은 100% 확정) |
| **보스 실체 (Q5)** | 지금 보스 패턴이 없다. 1차안: 기존 몬스터 3종의 **강화판**(HP ×4, 공격력 ×1.5, 크기 ×1.5, 패턴 3개 조합 + 특성 1개, `MonsterType.Boss`). 전용 장판 기믹·페이즈는 Roadmap대로 2차 |
| **보상** | 보스 드랍: 희귀 이상 확정 1개 + 골드 다량(수치 Q6). 결과 화면에 "보스 처치" 표시 |
| **데이터** | `FloorConfig.bossChance`, `bossPool`(MonsterDataSO 목록), `RunResult.BossesKilled` |
| **뷰/시청각** | 보스방 문틀 전용 색, 진입 시 보스 이름·HP 바 상단 표시, 잠금 SE |

## 11. 위험 요소

- **아트 의존**: 방 템플릿마다 벽·문 타일이 필요하다. art-sprites 세션의 던전 타일 초안과 문 규격(폭, 북쪽 벽 2칸)을 먼저 맞춰야 한다.
- **안개 초기화 범위**: `FogOfWarSystem.Initialize`가 바닥·벽 타일맵 전체를 순회한다. 조립이 끝난 뒤 1회 호출해야 한다.
- **TileSystem 예약**: 몬스터 복귀 이동이 문 칸 예약과 겹칠 수 있다(R5 테스트 항목).
- **HP 유지**: 층 이동을 씬 재로드로 하면 HP·MP가 최대치로 초기화된다(`CalculateStats`의 `_isInitialized` 분기). Q8이 "유지"면 `PlayerSessionData`에 HP·MP를 저장하고 허브 귀환 시 비워야 한다.
- **재생성 실패**: 막다른 방 수 부족으로 특수방 배정 실패 → 재시도 상한 + 폴백 필요.
