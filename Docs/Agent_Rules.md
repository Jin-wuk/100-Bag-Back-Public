# AI 에이전트 페어 프로그래밍 규칙 (Agent Rules)

본 문서는 기획자(개발자)와 AI 에이전트(Antigravity)가 페어 프로그래밍을 진행할 때, 에이전트가 반드시 지켜야 할 **행동 지침(Meta-Rules)**을 정의합니다.

## 1. 사고 과정 강제 (Adaptive Planning)
* **유연한 계획**: 대대적인 구조 변경이나 새로운 기능(Major)을 구현할 때는 코드를 바로 작성하지 않고 **요구사항 분석 -> 아키텍처 제안 -> 컨펌 요청**의 3단계를 거칩니다.
* **빠른 실행**: 밸런스 수치 조절, 단순 오타 수정 등 사소한 작업(Minor)은 계획서 없이 즉시 코드를 수정하고 사후 보고하여 개발 속도를 높입니다.

## 2. 에이전트 맞춤형 코드 모듈화 (Modular Chunking)
* **파일 시스템 직접 제어**: 에이전트는 코드 텍스트만 뱉어내는 대신, 기획자의 로컬 폴더(`Assets/Scripts/`)에 직접 파일을 생성/수정합니다.
* **바텀업 & 템포 조절**: 인터페이스나 데이터 클래스 등 '뿌리'가 되는 뼈대부터 작성하며, 한 턴에 **최대 2~3개의 파일만 수정/생성**한 뒤 기획자의 다음 지시를 기다립니다.

## 3. 유니티 표준 컨벤션 (MVP 맞춤형)
* **네이밍 룰**: `PascalCase`(클래스/메서드), `I`+`PascalCase`(인터페이스), `_camelCase`(프라이빗 필드), `camelCase`(로컬 변수).
* **캡슐화**: `public` 변수를 금지하고 `[SerializeField] private`를 사용합니다.
* **실용주의 인스펙터**: 기획자가 CSV로 제어하지 않는 '에디터 조절용 핵심 변수'에만 `[Header]`와 `[Tooltip]`을 달아 보일러플레이트(불필요하게 긴 코드)를 줄입니다.

## 4. 방어적 프로그래밍 (Fail-Fast vs Safe-Access)
* **필수 컴포넌트 (Fail-Fast)**: 반드시 있어야 할 컴포넌트(예: 내 무기)는 `Awake()`에서 할당 여부를 검사하고 없으면 `Debug.LogError(..., this)`를 뿜어 즉각 멈추게 합니다.
* **런타임 충돌 (Safe-Access)**: 충돌체 확인 등 불확실한 요소는 `TryGetComponent`를 사용하여 크래시 없이 부드럽게 무시합니다.
* **이벤트 호출**: 구독자가 없어도 터지지 않도록 `?.Invoke()`를 강제합니다.

## 5. 기존 코드 리팩토링 원칙 (Responsibility Separation)
* **의도 보존**: 기존의 퍼블릭 변수명과 메서드 시그니처를 유지하여 인스펙터 연결과 다른 스크립트의 의존성이 깨지지 않도록 보호합니다.
* **주석 공해 방지**: 소스 코드 내부에는 `// [Refactor]` 같은 불필요한 수정 태그를 달지 않습니다. 코드엔 '왜(Why)' 이렇게 짰는지 핵심만 남깁니다.
* **리뷰 분리**: 변경된 이유와 기존 코드의 문제점(Before & After)은 코드 주석이 아닌 **채팅창 대화나 마크다운 문서**를 통해 기획자에게 상세히 브리핑합니다.

## 6. 버전 관리 및 커밋 전략 (Git Strategy)
* **논리적 기능 단위 커밋**: 거대한 기능이 모두 완성될 때까지 기다리지 않고, 작은 청크(Chunk) 단위의 논리적 작업(예: '인터페이스 생성', 'CSV 로더 구현')이 끝날 때마다 즉시 커밋(`git add/commit`)합니다.
* **Conventional Commits**: 커밋 메시지는 `feat:`, `fix:`, `docs:`, `refactor:`, `chore:` 등의 접두사를 엄격히 사용하여 작성합니다.
