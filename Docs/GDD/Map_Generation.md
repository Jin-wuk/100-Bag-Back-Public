# 맵 생성 알고리즘 (Map Generation)

> [!NOTE]
> **개발 로드맵 및 MVP 범위 (Development Scope)**
> *   **MVP 단계 (현재)**: 전투 조작감(WASD 슬라이딩 + 마우스 에이밍), 몬스터 AI 카이팅, 탈출 동선 검증을 위해 **'수작업 고정형 맵(Fixed Map)'**을 우선 제작하여 테스트합니다.
> *   **확장 단계 (Post-MVP)**: 고정형 맵 테스트 완료 후, 아래의 **청크 기반 절차적 조립 알고리즘(2x2 노말, 3x3 하드모드)**을 단계적으로 적용합니다.

---

## 1. 청크 기반 조립 생성 (Chunk-based Generation) [확장 스펙]
맵의 절차적 생성(Procedural Generation) 시 순수 랜덤 알고리즘에 의존하지 않고, 구역(청크) 단위로 분할하여 조립하는 방식을 채택한다.
*   **난이도별 청크 규격**: 노말 모드는 2x2 (4청크), 하드 모드는 3x3 (9청크)으로 확장 구성.
*   **프리팹 바리에이션**: 각 청크 구역마다 1~3개의 디테일하게 수작업된 프리팹 바리에이션을 미리 제작.
*   **조합의 다양성**: 구역별 바리에이션 무작위 배치를 통해 최소한의 리소스로 높은 무작위성 확보.

## 2. 밸런스 통제와 확정적 룸 배치
완전한 랜덤 맵의 불합리성을 배제하고, 기획적 의도대로 밸런스를 통제할 수 있다.
*   예: "1번(좌측 상단) 청크에는 반드시 포션 상자 고정 배치", "중앙 청크에는 보스급 몬스터 배치" 등 청크 인덱스별로 명확한 난이도와 보상 설계 적용.

## 3. 이음새(Choke Point)와 수문장 배치
*   **목구멍(Choke Point) 형성**: 각 청크가 맞닿는 경계선은 플레이어가 다른 구역으로 넘어가기 위해 반드시 지나가야 하는 병목 구간.
*   **전투 강제와 ZOC**: 이 이음새 구역에 몬스터의 통제 구역(ZOC)을 배치하여 자연스러운 자원(마나, 체력) 소모 유도.

## 4. 유니티 구현 핵심 주의사항 (이음새의 규격화)
*   **내부 자유도**: 각 청크 프리팹 내부의 지형, 함정, 몬스터 배치는 바리에이션마다 자유롭게 구성.
*   **경계선 일치**: 다른 청크와 맞닿는 **동서남북 4면의 출입구 위치와 너비(좌표)는 모든 프리팹 바리에이션에서 100% 동일하게 일치**.

## 5. Spawner 기반 동적 엔티티 생성 & 인스턴스 초기화
청크 내부의 몬스터, 기믹, 플레이어 시작 지점, 포탈 등은 `Spawner` 컴포넌트를 통해 관리된다.
*   **Spawner Type**: `Monster`, `Gimmick`, `PlayerSpawn`, `PortalSpawn`.
*   **플레이어 시작 위치 (Player Spawn)**: 맵 조립 완료 후, 전체 청크 내 `PlayerSpawn` 지점 중 하나가 무작위 추첨되어 시작 위치 확정.
*   **탈출 포탈 위치 (Portal Spawn)**: 확정된 플레이어 시작 위치로부터 **가장 거리가 먼 후보군** 중 하나를 최종 탈출구로 개방.
*   **던전 초기화 및 복귀 (Instance Reset)**: 플레이어가 탈출 포탈에 진입하거나 사망 시, 던전 인스턴스(몬스터, 바닥 아이템 등)를 완전히 초기화(Unload/Destroy)하고 로비 상태로 전환.
