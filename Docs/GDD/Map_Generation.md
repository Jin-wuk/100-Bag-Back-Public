# 맵 생성 알고리즘 (Map Generation)

## 1. 9등분 청크 기반 생성 (3x3 Chunk-based Generation)
맵의 절차적 생성(Procedural Generation) 시 순수 랜덤 알고리즘에 의존하지 않고, 맵 전체를 3x3 형태의 9개 구역(청크)으로 분할하여 조립하는 방식을 채택한다.
*   **프리팹 바리에이션**: 각 구역(청크)마다 1~3개의 디테일하게 수작업된 프리팹 바리에이션을 미리 제작한다.
*   **조합의 다양성**: 9개 구역에 각각 3개의 바리에이션을 무작위로 배치하기만 해도, 3^9 = 19,683가지의 서로 다른 맵 구조가 도출된다. 이는 최소한의 개발 리소스로 유저에게 충분한 무작위성을 부여하는 최적의 가성비 구조다.

## 2. 밸런스 통제와 확정적 룸 배치
완전한 랜덤 맵의 단점(운에 따른 불합리한 맵 구조)을 배제하고, 기획적 의도대로 밸런스를 엑셀 데이터처럼 통제할 수 있다.
*   예: "1번(좌측 상단) 청크에는 반드시 포션 상자 고정 배치", "5번(정중앙) 청크에는 보스급 몬스터 배치" 등 청크 인덱스별로 명확한 난이도와 보상 설계를 적용할 수 있다.

## 3. 이음새(Choke Point)와 수문장 배치
*   **목구멍(Choke Point) 형성**: 각 청크가 맞닿는 경계선은 플레이어가 다른 구역으로 넘어가기 위해 반드시 지나가야 하는 병목 구간이 된다.
*   **전투 강제와 ZOC**: 이 이음새 구역에 몬스터의 통제 구역(ZOC)을 배치하면 유저는 원치 않더라도 전투를 회피할 수 없게 된다. 이는 유저의 마나(MP)를 강제로 소모시키고 치열한 자원 관리를 유도하는 자연스러운 레벨 디자인으로 이어진다.

## 4. 유니티 구현 핵심 주의사항 (이음새의 규격화)
유니티(Unity)에서 이 구조가 매끄럽게 연결되기 위해 가장 중요한 기술적 전제는 '이음새의 규격화(Standardization)'다.
*   **내부 자유도**: 각 청크 프리팹 내부의 지형, 함정, 몬스터 배치는 바리에이션마다 마음대로 구성해도 무방하다.
*   **경계선 일치**: 단, 다른 청크와 맞닿는 **동서남북 4면의 출입구 위치와 너비(좌표)는 모든 프리팹 바리에이션에서 100% 동일하게 일치**해야 한다.
*   **결과**: 이를 통해 런타임에 어떤 바리에이션 타일을 이어 붙여도 벽이 막히거나 길이 끊어지는 현상 없이 매끄러운 단일 맵처럼 렌더링된다.
